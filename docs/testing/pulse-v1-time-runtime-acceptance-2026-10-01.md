## Runtime architecture

Time + Pulse is an explicit composition of the existing daily Time window and the shared Pulse cycle engine:

- Steady Time still owns two native Shelly schedules using `Switch.Set` and does not install a script;
- Time + Pulse installs one run-on-boot script plus two native Shelly schedules;
- the native ON boundary calls `Script.Eval(id, "rq(true)")`;
- the native OFF boundary calls `Script.Eval(id, "rq(false)")`;
- the script owns Pulse phase timing only; it does not create a second repeating daily scheduler;
- on boot the script forces relay OFF and evaluates the current daily window once so reboot recovery is correct even before the next native boundary;
- the same shared `renderPulseCycleExecution()` engine used by the qualified Climate runtime drives Continuous, Cycles and Duration modes, initial delay, start phase and safe-OFF completion.

Persistent Time ownership stays backward-compatible: `kind: "time"` and the existing daily `config`/schedule IDs remain unchanged, while Time + Pulse adds optional `pulseRuntime: { script, pulse }` beside that config.

## Lifecycle and safety contract

The qualified adapter now owns these behaviors:

- installation requires a synchronized Shelly clock and two free native schedule slots;
- installation starts from explicit relay OFF, installs the run-on-boot script and then the exact ON/OFF `Script.Eval` schedule pair;
- partial installation rolls back created jobs/script and leaves relay OFF;
- pause cancels Pulse, disables both schedules, stops the script and leaves relay OFF;
- resume begins from safe OFF, re-enables both schedules and starts a fresh script/runtime cycle rather than resuming an unknown in-flight timer;
- a failed resume script start rolls the schedule state back and remains safe OFF;
- delete cancels Pulse, removes both schedule jobs and the script and explicitly finishes OFF even when intermediate deletion work fails;
- destructive lifecycle work verifies stored physical Shelly identity first;
- the old Steady Time updater rejects Time + Pulse before performing any RPC, preventing accidental downgrade/overwrite through the legacy editor path;
- reconciliation treats a wrong/stopped/hash-mismatched script or an incorrect schedule pair as changed/attention rather than trusting local metadata.
